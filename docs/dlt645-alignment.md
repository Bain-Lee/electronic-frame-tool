# DL/T 645 字典与本机规范对齐

本次以 `specifications/3-DLT645-2007.pdf` 为依据补齐 `protocols/DLT645.xml`，版本为0.7.0。Assistent 的 `DLT645.xml` 仅用于比较；未复制其中的省份、厂商或其他规约扩展。原始PDF与完整比较资料留在本机，不随源码或EXE分发。

## 依据与范围

以下页码均为PDF页面序号，从1开始；PDF第23页对应印刷页19。文件共115页，含红字补充内容，不能把全部补充表不加区分地称为最初发布的2007版正文。

| 本机原文位置 | XML整理及程序行为 |
| --- | --- |
| 表A.1，PDF23～33页 | 电能、明确列出的结算日与费率、当前及12结算日块；保留本机补充项及原文矛盾 |
| 表A.2，PDF33～45页 | 最大需量及发生时间、实际费率块、当前及12结算日块 |
| 表A.3，PDF45～48页 | 变量、三相/总值块、1～21次谐波及21项块 |
| 表A.4，PDF48～65页 | 事件、编程、购电等标识；明确单值解码，复合记录保留raw |
| 表A.5，PDF65～70页 | 参数名称、读写权限、明确数值/ASCII/时间；复合时区、时段、假日等结构保留raw |
| 表A.6，PDF70～93页 | 冻结标识及明示保留次数；明确的时钟、电能及需量子项解码；综合块/变量复合项保留raw |
| 表A.7，PDF93页；附录B，PDF108～109页 | 区分负荷请求附加参数与响应记录；响应保持raw，不把1/6/1字节请求参数当作响应值 |
| 本机安全补充表，PDF93～95页 | 安全读写标识按原文读写属性收录，密文、MAC、复合认证内容保留raw |
| 本机事件补充表，PDF95～107页 | DI3=10～1F的明确编码与“同上”关联范围；复杂记录保留raw |
| 附录C，PDF110～113页 | 状态字1～7、组合方式、通信速率、周休日及负荷/冻结模式的位定义；ERR继续由命令层解释 |

XML逐项保留 `sourceRef`，包含PDF页、提取表顺序和行号；跨页内容保留续页引用，位域另有附录C页码。提取表顺序与规范表号不同，查证时应同时核对页码和表A.x。`dataRange` 记录开放末端、ZZ关联等范围出处，不能直接作为可解码数据项。

当前从553个主编码行整理出40671种DI：22681个 `ready`、17986个 `raw`、4个 `ambiguous`，另有44个范围引用。数量包含费率、结算日、记录编号和补充表的范围展开，不是40671项设备联调或完整业务支持证明。`ready` 中也包含边界明确、仅显示原始字节的字段。

## 对旧实现和参考文件的修正

| 差异 | 本版处理 |
| --- | --- |
| 645原来依赖代码中的常用DI表，选择器只有14项 | 名称、检索、长度、单位、小数位、符号、时间和位域改从DLT645.xml读取；不再维护第二套645数值字典 |
| 参考电能/需量费率块使用固定256/512字节 | 按表A.1/A.2的注释使用实际返回的总量及已配置费率，分别按4/8字节一项解释；截断不提交部分字段 |
| 组合电能或组合无功需量的方向 | 按对应表注释处理最高位符号；需量为3字节值加5字节发生时间 |
| 日期/结算日易被当作普通BCD | 日期顺序为WW、DD、MM、YY，0为星期日；结算日DDhh的9999显示“未设置结算日” |
| 按范围展开时混用结算日模板 | 只展开原文明示的00～0C范围；剩余/透支量及仅当前/上1周期项不扩成12个结算日 |
| 费率电价、密码等级编号 | 电价按DI0的1～63编号，4位小数；密码DI0=01～0A对应0～9级，仅写 |
| 多行/跨页权限与稀疏单位列 | 以原页坐标对齐星号和单位；04000109的写权限来自PDF66页，不沿用默认读权限 |
| 状态、特征和模式字在A.5写为NN/XXXX | 按附录C拆位，不把F0等合法位组合报为非法BCD；未确认的指示字保留RAW |
| 负荷A.7的数据格式 | 写入专门的 `request` 元数据；当前“读取数据项”表单缺少附加参数时拒绝生成，并指向原始HEX入口 |
| D5=1首帧及12H后续应答 | 未重组前保留原始数据，不当完整块解码；后续应答不标为请求 |

与参考文件的本机比较中，参考有13258个dataItem、12848个合法8位HEX唯一DI，另有23种不符合8位HEX的标识。本版未匹配到其中7840种合法标识；7605种属于0060～0068精确电能系列，其余包括0561精确冻结、0610/0612及厂商用途等。**未匹配只表示未纳入本机规范生成集合，不能据此断言它们在其他版本或扩展规约中无效。**

例如参考中的油变装置、空调控制、主动上报和广播校时记录扩展没有并入本机基准。参考的固定块长度与本版实际费率结构不同，也不意味着所有长度差异都是同一种错误。完整逐DI比较CSV留在 `.work/dlt645-alignment/reference-differences.csv`。

## 保留的原文矛盾与实现边界

- `04000306/04000307`：本机表A.5都命名为“电流互感器变比”，不自行将其中一项改成电压互感器变比。
- `00900200/00900201`：本机表A.1名称写为剩余/透支电量，单位却为“元”，保留原名并标为待确认，不自行改称金额。
- 四项均显示“原文待确认”，不自动解码，也不进入用途数据项选择器。
- 阶梯表只展开原文明列的1、2，不猜测开放省略号的末端。时区、日时段、综合冻结、复杂事件、负荷响应、安全结构等保留raw，尚未把全部复合布局变为可执行结构。
- 读响应仍受645单帧长度限制；费率上限定义不等于可以在一帧传回全部费率。当前没有会话式分帧重组、密码认证、MAC计算、设备执行条件校验或真实设备联调。

## 统一维护与复现

三份字典共同位于 `protocols/`，共用 `ProtocolCatalog` 解释器。CSG按DI、AFN、方向选择；645没有AFN，使用DI、命令功能 `function="11,14"`、方向及读写属性。XML描述数据项，帧起止符、长度、地址、±33H、CS及命令交互仍由各自的编解码器处理。具名用途的控件和编码规则仍在用途代码中，不是任意XML自动生成表单。

645字典由已纳入版本管理的生成器维护，修改时先改生成规则或明确条款映射，再生成XML、审查差异并构建。不要直接修改生成结果后遗漏生成器，否则下次生成会覆盖修改。

```powershell
python -X utf8 tools/GenerateDlt645Catalog.py
# 可选：比较参考配置，不将其内容作为生成依据
python -X utf8 tools/GenerateDlt645Catalog.py --reference D:/AIproject/Assistent/_internal/app/config/DLT645.xml
.\Build.ps1 -Test
```

生成器仅在开发时需要Python 3.9+、pdfplumber和本机PDF；可用 `--standard` 指定PDF路径，`--evidence` 指定本机提取资料目录。汇总JSON、提取表和完整差异CSV默认写入被Git忽略的 `.work/dlt645-alignment/`。本次使用Python 3.12.14、pdfplumber 0.11.9；生成器不通过导入或执行Assistent来建立字典。

命令行构建与项目文件都内嵌三份XML。修改后重新构建单个EXE，运行时不依赖Python、原始规范、Assistent或外部XML；没有新增热重载、轮询或哈希缓存。
