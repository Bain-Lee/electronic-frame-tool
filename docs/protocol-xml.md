## FrameTools 的实现

`ProtocolCatalog.cs` 从内嵌资源读取一次字典，选择同时匹配协议、DI、功能和方向的唯一项：CSG功能属性为AFN，645为命令功能11/14。重复或不明确的定义不能用于自动解码，不采用通用表达式求值、外部路径覆盖或热重载。

业务层继续沿用已验证的解码分支，本地名称改从XML读取；未覆盖的明确字段布局使用XML补充。本版上行仅在原有首个明文参数和当前数据分支中补充XML解码，不扩大加密写参数的解析范围。按用途组帧还使用XML的名称、AFN和状态筛选数据项，具体控件与编码仍由用途代码实现，详见 [按用途组帧说明](purpose-composer.md)。

字段先暂存，确认长度与值有效后才写入显示结果。截断或无效BCD不会留下半套数值字段，也不改变原有帧结构是否合法的判断。上行只消费已明确首项的长度，剩余字节不猜作下一个DI或PW/MAC。

BIN全FF可以是合法数值；BCD全FF按缺失处理。原始字节、源偏移和原有帧诊断继续保留。

645费率块使用明确步长与实际剩余长度，时间支持日期/星期及结算日格式，9999结算日先按哨兵值解释。D5=1首帧和12H后续应答不在未重组时作为完整数据解码。负荷请求缺少附加参数时不会生成错误的普通读取帧。
