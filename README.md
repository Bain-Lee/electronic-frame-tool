# FrameTools 电力报文工具

Windows 离线桌面工具，用于 DL/T 645-2007、南网本地通信模块接口和南网上行通信规约的报文解析及组装。当前版本为 **0.2.1，支持自动识别和连续多帧解析**。

## 运行

构建产物：`artifacts/FrameTools.exe`。双击运行，无需 Python、Node.js 或网络连接。

- 目标环境：安装了 **.NET Framework 4.8** 的 Windows 10 / 11。
- EXE 为 AnyCPU 托管程序，不包含 .NET Framework 运行时。
- 不需要管理员权限。当前没有设备收发、自动更新或网络上传功能。

**“帧结构校验通过”只表示已实现的字节结构检查通过，不代表业务字段全部合法、认证成功或真实设备会接受该命令。** 未知 DI 保留原始字节；上行 PW/MAC 不计算、不验证、不解密，也不猜测多信息体边界。

## 使用

1. 保持“自动识别规约”勾选，在“报文解析”页粘贴一条或多条 HEX。支持有空格、无空格、无换行及混合规约；无需先选规约或点击解析。
2. 输入后约 350ms 自动解析；持续追加内容时也会定期解析。`Ctrl+Enter` 可立即解析。
3. “自动整形”区按报文分行、按字节加空格，原始输入保持不变。通过“逐条查看”列表或上一条 / 下一条查看每帧字段，点击字段可定位整形区字节。
4. 在“组装报文”页填写参数，生成结果后可复制或发送到解析页检查。

末尾半帧或半个字节会保留，追加完整后自动重新解析。错误帧显示诊断，未识别数据也会显示为片段，不会静默删除。若多个规约均满足结构和校验，工具提示歧义；取消“自动识别规约”后，使用顶部下拉框手动指定。该下拉框同时决定组帧使用的规约。

例如直接粘贴 [三协议连续串](examples/mixed-continuous.hex)，会自动分成 645、本地、上行三条报文。它们之间没有空格或换行也可以解析。

输入范围是 HEX 报文字节；设备日志中的 `TX` / `RX` 标签、时间戳或说明文字需要先移除。程序不会通过删除任意非 HEX 字符来猜测报文内容。

组帧时的输入约定：

- **645**：地址按高字节在前输入，如 `000000000001`；DI 按 `DI3…DI0` 输入，如 `00010000`；业务数据输入减 33H 后的明文字节。程序自动调整地址、DI 字节序并加 33H。读通信地址时用 C=`13` 并清空 DI。
- **南网本地**：C 的 D5 为 ADD，置 1 时填写源、目的地址，均按高字节在前输入；DI 如 `E8000301`。SEQ 为完整 8 位数值，输入格式仍为 HEX，例如 `FF`。
- **南网上行**：地址按实际传输顺序填写 `A1(3) + A2(3) + A3(1)`；业务区输入完整的 DA、DI、数据及可选 PW、Tp。程序不转换业务区字节序，不做 ±33H。
- C、AFN、SEQ 均按 1 字节十六进制输入。

输入内容变更后自动重新解析；组帧参数变更后需要重新生成。程序不会自动修正导入报文的校验和。

## 构建与测试

在 Windows PowerShell 中执行：

```powershell
.\Build.ps1 -Test
```

脚本使用本机 .NET Framework C# 编译器，不下载 NuGet 包，不安装全局工具。产物输出到 `artifacts/`。也可以通过 Visual Studio 打开 `src/FrameTools/FrameTools.csproj`，需要相应的 .NET Framework 4.8 开发组件。

如 PowerShell 的当前执行策略阻止脚本，可以仅为本次进程执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1 -Test
```

验证情况见 [验证记录](docs/verification.md)，本次审查及修复见 [Code Review 记录](docs/code-review.md)。

