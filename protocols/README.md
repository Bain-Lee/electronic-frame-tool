# FrameTools 规约 XML

本目录按 `specifications/` 中的两份本机原文重建业务数据字典，不修改 Assistent 的原配置。文件名保留 CSG13、CSG16 的常用叫法，实际版本以 XML 的 `source`、`version` 为准。

| 文件 | 本机依据 | 定义数量 |
| --- | --- | --- |
| `CSG13.xml` | 上行通信规约，2024版V2.0，封面2026年8月 | 9959个定义、9955种唯一DI，包含原文范围编码的展开 |
| `CSG16.xml` | 本地通信模块接口协议（试行），独立版次未确认 | 144个方向定义、108种唯一DI |

这些数量是字典记录数，不是已验证的解析功能数量。上行文件有5508个 `ready`、4449个 `raw`、2个 `ambiguous` 定义；本地文件分别为126、12、6个。

公开XML保留数据定义、技术说明及 `sourceRef` 出处引用，不附带整份原文正文和原表。完整核对副本保存在本机Git排除目录 `.work/protocol-catalog/full-source/`，其中 `sourceTables` 为原表，`sourceText` 为提取正文。`sourceRef` 的源表顺序号用于核对本机资料，不替代规范中的章节、表号和原始图示。

## 状态

- `ready`：有明确的固定长度或受支持的字段布局。部分字段仅确认字节边界，以 `RAW` 展示；这不表示已实现其全部业务含义、安全认证或交互流程。
- `raw`：保留了原文名称、字段表或布局引用，当前不能唯一确定可执行的消费规则，不自动解码。
- `ambiguous`：原文存在编码、长度或内容冲突，保留证据，等待确认。

上行 E0000134 的说明与字节数列、本地邻居主节点查询和文件失败节点查询的总表与正文等矛盾均已标注。没有把 Assistent 中缺乏本机规约出处的9项分钟采集扩展加入基准字典。

## 选择与字段

数据项由 `id`、`afn` 和 `dir` 共同选择；协议由所属文件确定。`afn` 是十六进制逗号列表，`dir=0` 为下行、`dir=1` 为上行，可用 `0,1` 表示共同定义。不能仅按 DI 选择首条记录。

本版只包含本机原文基准“南网”，没有混入 Assistent 的省份扩展。两文件采用 FrameTools 的明确格式，不作为 Assistent 原查找器的直接替换配置。

| 元素 | 含义 |
| --- | --- |
| `name` / `length` | 名称、字节长度；`unknown` 必须依靠明确子字段定位，不能自动吞下剩余数据 |
| `type` | `BIN` 小端二进制、`BCD`、`ASCII` 或原始字节 `RAW` |
| `decimal` / `unit` / `sign` / `time` | 小数位、单位、BCD符号和明确时间格式 |
| `splitByLength` | 按序排列的字段 |
| `repeat count="字段名"` | 根据先前数值字段重复记录；`skipValue` 用于原文明示的省略条件，如多播任务FFFF不携带地址列表 |
| `lengthrule` | 只支持先前字段名、整数乘字段名，不执行通用表达式 |
| `lengthIf` | 根据先前字段的掩码值选择长度，如D4决定任务报文长度字段为1或2字节 |
| `value` / `splitbit` | 十进制枚举值、单bit或bit范围含义 |

例如新版 APP 控制采用32字节名称和1字节控制状态；安全信息2025版明确列出106字节结构；多播任务和任务详情包含D4控制的长度。文件内容及内层报文仍可用RAW保留，未冒充校验、解密或完整645解析。

## 构建与使用

运行仓库根目录的 `Build.ps1 -Test`。命令行和项目文件均将两个 XML 嵌入 EXE，运行时惰性加载一次，仍以单个 `FrameTools.exe` 交付。

修改 XML 后需要重新构建；当前不提供外部文件覆盖、输入时重载或文件轮询。这样沿用现有单EXE交付方式，避免引入路径搜索和额外配置行为。

运行时保留已验证的业务分支，其他符合明确布局的数据项由XML解释。本地名称来自XML；上行首个明文参数/当前数据项可以使用XML补充名称和字段。加密写参数、未确认的多信息体及认证域继续保留原始内容。

参见 [XML接入与Assistent参考](../docs/protocol-xml.md)。
